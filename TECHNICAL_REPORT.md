# SXE: Sparse eXtra Ensembles

**Batch-boosted, holdout-pruned, sparsely re-weighted histogram trees**

Technical report, v3 (final). This document supersedes and incorporates the incremental `REPORT.md` and is the reference documentation for the code in this repository.

---

## 1. Summary

SXE is a tree-ensemble method that combines the parallel, randomized tree growth of extremely randomized trees with the bias reduction of gradient boosting and a convex post-hoc sparsification step. The final algorithm (v3) works as follows: features are quantile-binned once into at most 256 histogram bins; a dictionary of trees is generated by *batch boosting* — small batches of randomized, subsampled trees grown in parallel against the current residual, added with shrinkage, early-stopped on a validation fold; each tree is pruned on its own out-of-subsample holdout at a per-tree random strength; and a single non-negative lasso over *batch-average* prediction columns re-weights the boosting trajectory and physically deletes batches that contribute nothing.

On nine benchmark datasets, with **both libraries tuned** by random search of equal budget and model size accounted the same way on both sides, SXE wins on accuracy on four and loses on five, and carries the smaller model on five of nine (by up to 11.8x) while being larger on four. The clearest result in the report is a negative one: SXE's *defaults* give up a median 9.5% error reduction to tuning where LightGBM's give up 3.3%, on eight of nine datasets, and not one winning configuration used the default tree depth. The tuned method is competitive; the shipped defaults are not. Sections 7-8 give full numbers and caveats.

The design has three distinguishing ideas relative to standard gradient-boosted trees:

1. **Per-tree holdout reduced-error pruning at randomized strengths.** Every tree is grown on a random subsample; the complement is that tree's private holdout. A single bottom-up pass collapses any subtree that does not beat its collapsed leaf on holdout SSE by a per-leaf penalty λ, with λ drawn log-uniformly per tree. The ensemble therefore spans a spectrum of bias–variance trade-offs, and the final weight fit chooses among them.
2. **Batch-parallel boosting.** Trees within a batch are independent and grown concurrently; only the batch-level residual update is sequential. This preserves most of boosting's fine-grained bias reduction while exposing tree-level parallelism that sequential GBDT cannot.
3. **One-shot sparse non-negative re-weighting of the trajectory.** By the stagewise≈lasso correspondence (LARS), fitting a positive lasso over the generated columns is a convex stand-in for the greedy stagewise fit that produced them. Fitting it over batch-average columns makes its cost independent of tree count and lets it prune whole steps of the trajectory. A diagnostic (Section 6.4) shows the lasso compresses the ensemble ~10× at no accuracy cost.

Lineage: the dictionary-then-sparse-combination structure is Friedman & Popescu's ISLE with Breiman's non-negativity constraint (stacked regressions); the pruning is classical reduced-error pruning against honest holdout data; the tree grower borrows LightGBM's histogram machinery (binning, histogram subtraction, exclusive feature bundling, optional leaf-wise growth) and ExtraTrees' randomized thresholds (Geurts, Ernst & Wehenkel).

## 2. Notation and setting

Training data $(x_i, y_i)_{i=1}^n$, $x_i \in \mathbb{R}^p$. Regression minimizes MSE. Binary classification is handled as regression on $y \in \{0,1\}$ (the Brier-score / stacked-classifier reduction): leaf means are probability estimates, and predictions are clipped to $[10^{-6}, 1-10^{-6}]$; MSE splits on 0/1 targets are equivalent to Gini up to constants. Multiclass is not implemented.

The fitted model is

$$\hat{y}(x) = \beta_0 + \sum_{b \in \mathcal{S}} w_b \cdot \frac{1}{B}\sum_{t \in \text{batch } b} T_t(x), \qquad w_b \ge 0,$$

where $T_t$ are pruned trees, $B$ is the batch size, and $\mathcal{S}$ is the sparse set of batches surviving the weight fit. Members outside $\mathcal{S}$ are deleted from the model object.

## 3. The pipeline in detail

### 3.1 Global quantile binning

`QuantileBinner` (Python, `src/sxe/binning.py`) computes per-feature quantile edges from a subsample of at most 50,000 rows: 255 interior quantile points, deduplicated, giving at most 256 bins per feature. `transform` maps values via `searchsorted(edges, x, side='right')` to bin ids in `uint8`. All downstream stages — growth, holdout routing, pruning, member prediction, the weight-fit design matrix — operate on this one integer matrix (column-major for the C++ core). A uniform random threshold drawn by an extremely randomized split on binned data is exactly a random bin cut-point, so binning and ExtraTrees-style splitting compose without approximation.

### 3.2 Exclusive feature bundling for binary columns (EFB)

`BinaryBundler` (Python, `src/sxe/bundling.py`) implements LightGBM-style EFB restricted to strictly binary columns. Columns with values in {0,1} are ordered by nonzero density and greedily assigned to the first bundle whose used-row mask they do not overlap (zero conflict tolerance, bundle size ≤ 250). Bundles of size ≥ 2 become a single small-integer column: 0 if no member is active, else the 1-indexed position of the active member; singletons pass through. The transform is lossless up to the ordinal encoding of the bundle (a threshold split on a bundle selects a *contiguous* group of categories rather than one-vs-rest, but trees compose splits, and empirically accuracy was unchanged). On Covertype this compresses 54 features to 12 (bundles of 5 wilderness and 39 soil indicators) and cuts histogram work ≈ 4.5×.

### 3.3 Tree growth

Trees are grown by the C++ core (`sxe.cpp`) on the binned matrix. Split quality uses the variance-reduction proxy

$$G(f,t) = \frac{S_L^2}{n_L} + \frac{S_R^2}{n_R} - \frac{S^2}{n},$$

where $S$, $S_L$, $S_R$ are target sums and $n$, $n_L$, $n_R$ counts in the node and its children under "bin ≤ t". A candidate is invalid if either child would fall below `min_samples_leaf`.

**Candidate generation.** At each node, $K$ distinct candidate features are sampled without replacement (partial Fisher–Yates), $K = \mathrm{round}(\phi\, p)$ with $\phi \sim U(\texttt{feat\_lo}, \texttt{feat\_hi})$ drawn once per tree. Per candidate feature, cut-points are evaluated either as (a) `n_thresh` random thresholds uniform on the feature's occupied bin range — the extremely randomized mode — or (b) the exact best cut by a prefix scan over all bins (`argmax_bins=1`). With retained histograms both cost $O(\text{bin span})$, so the exact scan is essentially free; the choice controls split quality versus member diversity and is a per-dataset knob (Covertype favored random cuts; the regression tasks favored exact cuts).

**Depth-wise growth with histogram subtraction (hybrid).** Nodes with at least `hybrid_min` samples (default 600) retain an all-feature histogram (`Hist`: `int32 cnt` and `double sum` laid out `[feature*256 + bin]`). Candidates are evaluated from prefix sums of this histogram — no data pass. After partitioning the node's index range in place, the *smaller* child's histogram is built from data in $O(|\text{small}| \cdot p)$ and the larger child's is derived by an in-place parent-minus-child subtraction, so the parent's buffer is reused and at most depth+1 buffers are live per thread (buffers are pooled). Children below `hybrid_min` recurse into the legacy grower, which builds per-candidate 256-bin histograms with touched-bin clearing and therefore has no memset overhead on small nodes. The threshold trades the full scheme's `p×256` clearing cost against its per-row savings; 600 worked across all three datasets.

**Leaf-wise growth (optional, `max_leaves > 0`).** A best-first alternative in the style of LightGBM: a max-heap keyed on gain holds pending leaves with their histograms and precomputed best splits; the highest-gain leaf is split, children histograms are obtained by the same small-fill-plus-subtraction step, each child's best split is evaluated and pushed if it clears depth/size/gain floors, and growth stops at the leaf budget. Node ids satisfy parent < children, so the bottom-up passes below remain valid in both modes.

**Per-tree randomization.** Each tree draws: `max_depth` from `depth_choices` (0 ⇒ capped at 64), `min_samples_leaf` log-uniform on `leaf_range`, the feature fraction $\phi$, and a row-subsample rate uniform on `subsample_range` (sampling without replacement). Seeds derive from `splitmix64(seed + c·tree_index)`, so results are deterministic and independent of thread count.

### 3.4 Holdout reduced-error pruning with a complexity penalty

The rows not in a tree's subsample are its holdout. After growth, the holdout is routed through the tree once, accumulating $(n_h, \sum y, \sum y^2)$ at every node on each row's path. A single bottom-up pass (descending node id) then computes, per node, the holdout SSE of collapsing to a leaf,

$$\mathrm{SSE}_{\text{leaf}} = \textstyle\sum_h y^2 - 2\mu \sum_h y + n_h \mu^2,$$

with $\mu$ the node's *training* mean, and collapses the node iff

$$\mathrm{SSE}_{\text{leaf}} \le \mathrm{SSE}_{\text{subtree}} + \lambda\, \hat\sigma^2_h\, (L_{\text{subtree}} - 1),$$

where $\hat\sigma^2_h$ is the root holdout variance and $L$ the subtree's (post-collapse) leaf count. λ = 0 removes exactly the splits that do not help held-out data ("dead wood"); larger λ gives nested, increasingly aggressive subtrees — a holdout analogue of weakest-link pruning. In v3 each tree emits **one** member, pruned at $\lambda \sim \text{log-}U(\texttt{lam\_lo}, \texttt{lam\_hi})$, so pruning-strength diversity lives *across* trees and the weight fit arbitrates. Collapsed nodes are exported as leaves carrying their training means.

**Small-holdout guard.** If the holdout has fewer than $\max(50, n/50)$ rows, the tree is emitted unpruned. Without this guard, subtrees never visited by a near-empty holdout satisfy $0 \le 0 + \lambda \cdot (\cdot)$ and collapse spuriously — in the worst case to a stump. This bug measurably degraded California accuracy before the fix (Section 6.5).

### 3.5 Batch-boosted dictionary generation

`sxe_boost` runs the whole generation loop natively. With residual $r \leftarrow y$ on the training partition and $F_{\text{val}} \leftarrow 0$:

for batch $b = 1, \dots, \texttt{max\_batches}$:
1. grow $B$ trees in parallel (OpenMP, dynamic schedule) on $(X, r)$, each with its own subsample, hyperparameters, holdout pruning, and export; each tree's predictions on the full training partition and on the validation fold are computed inside the parallel region;
2. update $r \leftarrow r - \frac{\nu}{B} \sum_{t=1}^{B} T_t(X)$ and $F_{\text{val}} \leftarrow F_{\text{val}} + \frac{\nu}{B} \sum_t T_t(X_{\text{val}})$;
3. early-stop if validation MSE has not improved by `tol` (set to $10^{-4}\,\mathrm{Var}(y_{\text{val}})$) for `patience` consecutive batches.

Each batch is one shrunk correction of size ν built from a mini-forest, so the generator interpolates between a random forest (one huge batch) and stochastic gradient boosting (B = 1); B ∈ [4, 16] preserved almost all of boosting's accuracy while keeping the parallel width. Trees fit residuals, and their holdout pruning is evaluated against the same residual target, which is the correct objective at that stage.

### 3.6 The one-shot sparse non-negative weight fit

Let $P \in \mathbb{R}^{n_{\text{val}} \times M}$ hold all members' predictions on the validation fold. In batch-group mode (default), columns are averaged within batches, $P_b = \frac{1}{B}\sum_{t\in b} P_{\cdot t}$, giving one column per batch — the weight-fit cost becomes independent of tree count. The weights solve a positive elastic net (pure lasso by default) with intercept:

$$\min_{w \ge 0,\, \beta_0} \; \tfrac{1}{2n_{\text{val}}}\lVert y_{\text{val}} - \beta_0 - P_b w \rVert^2 + \alpha \lVert w \rVert_1,$$

with α chosen by 3-fold cross-validation over ~12–20 alphas on the validation fold, using **precomputed Gram matrices** (`precompute=True`), which cut the fit from ~20 s to 1–5 s at thousands of columns and to 0.02–0.3 s at hundreds. Non-negativity (Breiman) yields sparser, more stable solutions; the intercept absorbs shared bias; weights are deliberately not constrained to sum to one. Batches with zero weight are deleted; surviving members receive weight $w_b / B$. If the CV solution is entirely zero, a tiny-alpha positive fit is used as a fallback. Selection is intentionally on held-out data: fitting weights in-sample makes the deepest trees absorb everything.

The legacy multi-round class (`CppSXE`) retains a per-round variant: full CV on the first and final rounds, single warm fixed-alpha fits (0.7× the previous α) between, and a narrowed final grid $\alpha_1 \cdot \mathrm{logspace}(0.5, -1, 10)$.

### 3.7 Prediction and model size

Prediction routes binned rows through the selected trees and forms $\beta_0 + \sum w\,T(x)$ (`sxe_predict_weighted`). Model size is accounted the same way for every library compared: 13 bytes per internal node (`feat` 4, `thr` 1, `left` 4, `right` 4), 8 bytes per leaf (`value`), plus the bin table needed to map raw features to bin ids at predict time (255 edges x 8 bytes per feature the model indexes, which for SXE is the post-bundling count). Earlier versions of this report compared an SXE format estimate against pickled baselines, which overstated the difference by 2-5x; Section 7 uses one formula on both sides. Note that leaf count is *not* a format-free proxy for size, and the size result does not go SXE's way everywhere -- Section 7.1 has it smaller on five of nine datasets and larger on four.

**The compact format is not yet the format SXE writes.** `Ensemble::serialize` stores, for every node, `feat` (4) + `left` (4) + `right` (4) + `thr` (1) + `val` (8) + `gain` (8) = 29 bytes: `gain` is read only by `feature_importances_`, leaves carry four fields that are always `-1`/`0`, and internal nodes carry a `val` that `predict_row` never reads. Measured on Friedman1 at defaults, `serialize()` writes 469 kB where the formula says 164 kB -- 2.9x. Splitting the node arrays by type would make the advertised number the real one; until then, the size column is what SXE's format *could* be.

### 3.8 Complexity

Per tree, growth is $O(n_s(p + d))$ with subtraction at large nodes (histogram fills are dominated by smaller-child sums, ≤ $n_s p/2$ per level) plus $O(n_s d)$ for partitions, $O(n_h d)$ holdout routing, and $O(\text{nodes})$ pruning; $n_s$, $n_h$, $d$ are subsample size, holdout size, and depth. Residual updates add $O(n d)$ per tree. The weight fit costs one Gram, $O(n_{\text{val}} M_b^2)$ for $M_b$ batch columns, plus coordinate descent on $M_b \times M_b$. Measured single-core grower throughput: ≈ 27.8k leaves/s versus LightGBM's ≈ 13.9k leaves/s on Covertype — the wall-clock differences in Section 7 come from *how much* structure each method builds, not per-leaf cost.

## 4. Repository contents and build

The work now ships as an installable package. The reference prototype that produced the results below is retained under `reference/` and is used as a parity oracle: the packaged core reproduces it bit-for-bit on all three datasets.

**Package (`src/sxe/`, installed as `sxe`):**

| File | Role |
|---|---|
| `_core.cpp` | C++ core: hybrid depth-wise grower with histogram subtraction, leaf-wise grower, extremely-randomized and exact-cut evaluation, holdout routing and pruning, batch-boost generation, member/weighted/batch-mean prediction, serialization. pybind11 boundary; a `std::thread` pool rather than OpenMP, so there is no runtime to bundle and `n_jobs` is explicit. |
| `estimator.py` | `SXERegressor`, `SXEClassifier`. scikit-learn estimators; both pass `check_estimator` in full. |
| `binning.py` | `QuantileBinner` — global quantile binning straight to `uint8`. |
| `bundling.py` | `BinaryBundler` — exclusive feature bundling (EFB) for binary columns. |

**Reference prototype (`reference/`, not installed):**

| File | Role |
|---|---|
| `sxe.cpp` | Original C API core with OpenMP, including the v2 multi-round `sxe_grow`. |
| `cpp_sxe.py` | ctypes wrapper: `CppSXE` (v2 multi-round), `CppSXEBoost` (v3). |
| `sparse_extra.py` | Pure-Python v1 prototype on sklearn `ExtraTreeRegressor` with CCP-path variants. |
| `benchmark.py`, `cpp_benchmark.py`, `bench_final.py` | v1/v2 benchmarks; source of the RF numbers. |
| `results_v3.csv` | Raw v3 output. |

Install:

```bash
pip install sxe          # or: pip install -e .  from a checkout
```

Needs a C++17 compiler and CMake to build from source; NumPy and scikit-learn at runtime (developed on Python 3.12, scikit-learn 1.7, NumPy 2.3); `lightgbm` only for the benchmark scripts. Optimisation flags are deliberately portable — `-march=native` measured no reproducible speedup on these datasets, consistent with the memory-bound histogram loops in Section 3.8, so wheels give it up for nothing.

Quickstart:

```python
from sxe import SXERegressor

model = SXERegressor(random_state=0).fit(X_train, y_train)
pred  = model.predict(X_test)          # SXEClassifier for classification
print(model.summary())                 # trees grown/kept, leaves, size, timings
```

Parameter names follow scikit-learn's `HistGradientBoosting*` vocabulary where the concepts match; Section 5 gives the mapping from the names used in this report.

The batch-group lasso (`group_by_batch` in the prototype) is now unconditional: batch-average columns are formed inside the C++ core, which also keeps the weight-fit design matrix at n_val × n_batches instead of n_val × n_members.

Tuning guidance distilled from Section 6: smooth low-dimensional signal wants fine trajectories (small ν, many batches, small B, mild subsampling 0.85–1.0, exact cuts, `max_leaves≈63`); high-dimensional/one-hot data wants depth 10–14, random cuts (`argmax_bins=0`, `n_thresh=3`), EFB, moderate subsampling; noisy data with irrelevant features tolerates aggressive subsampling (0.2–0.4) and large ν with tight patience, which is where the speed comes from.

## 6. Evolution and ablations

The final design was reached through measured iterations; the deltas are the evidence for each component.

> **Provenance.** The figures in this section were measured on the original prototype under Linux/libstdc++ and are single-seed. They are kept as the *relative* evidence for each design decision — the direction and rough magnitude of each delta — and are deliberately not restated to match Section 7, which is a five-seed re-measurement on macOS/libc++. Absolute values here will not reproduce exactly; see the cross-platform caveat in Section 8.

**6.1 v1 (Python, sklearn ExtraTrees + CCP variants + per-round ElasticNetCV).** Established the pipeline. Boosted multi-round beat RandomForest everywhere (e.g. Friedman 1.088 vs 1.443 RMSE) at 20–40× smaller models; a single-round dictionary landed only at RF level — the residual rounds supply essentially all accuracy beyond bagging. LightGBM matched only on the noisy task.

**6.2 v1→C++ core.** Same algorithm with holdout pruning replacing the CCP approximation and two random cuts per feature: 5–10× faster growth, and the holdout pruning itself improved accuracy (Covertype AUC 0.9528 vs 0.9480), consistent with pruning decisions made against genuinely held-out data. Gram precompute cut the weight fit 6×.

**6.3 v2 (histogram subtraction + EFB).** Subtraction gave ~1.6× on growth; EFB a further ~2.4× on Covertype with unchanged accuracy. Profiling showed the grower already produced ~2× more leaves/s than LightGBM; remaining wall-clock gaps were structure volume and pipeline overhead. Covertype became a clean three-axis win at this stage; Friedman was accuracy-tied but slow (fixed-size dictionary vs LightGBM's early stopping); California accuracy plateaued near 0.47.

**6.4 v3 (batch boosting + batch-group lasso).** Replacing coarse rounds with fine shrunk batches, early stopping, and a single group lasso: Friedman flipped to a three-axis win (0.9-of-a-second grower, 0.12 MB model); shallow-tree defaults broke Covertype (AUC 0.92), recovered by depth 10–14 with random cuts — Covertype genuinely needs deep, wide-candidate trees. Per-member lasso costs exploded at thousands of columns (7 s); batch-group columns made the fit 0.02–0.3 s with no accuracy change. A diagnostic comparing lasso weights to raw generation weights (uniform ν/B) found test-equal accuracy with ~10× compression — the lasso's role is compression and trajectory pruning, not correction.

**6.5 The small-holdout bug.** Subsample rates near 1.0 leave near-empty holdouts; unvisited subtrees then satisfy the collapse inequality trivially and trees degrade toward stumps. Guarding (emit unpruned below a holdout floor) improved California from 0.4504 to 0.4437 and is the reason mild-subsampling configs work at all.

**6.6 Leaf-wise growth.** Implemented cleanly but did not break the California plateau (63-leaf ≈ depth-wise best; 31-leaf worse) — evidence the residual gap there is not tree shape.

## 7. Benchmarks

**Setup.** Nine datasets, chosen so that each stresses a different property, and several
stress properties SXE does not have:

| Dataset | Shape | Task | What it is here to test |
|---|---|---|---|
| California housing | 20,640 × 8 | regression | smooth low-dimensional signal, small n |
| Friedman1 + 20 noise features | 25,000 × 25 | regression | known signal buried in noise (RMSE floor ≈ 1.0) |
| Superconductivity | 21,263 × 81 | regression | real regression, many correlated features |
| Covertype 2-vs-rest, subsampled | 30,000 × 54 | classification | the original reference point |
| Covertype 2-vs-rest, full | 581,012 × 54 | classification | large n, where gradient-boosting scaling shows |
| Adult | 48,842 × 14 | classification | categoricals of cardinality 2–41, with missing values in them |
| Bank marketing | 45,211 × 16 | classification | categoricals of cardinality 2–12, no missing values |
| Letter recognition | 20,000 × 16 | 26-class | the cost of the one-vs-rest reduction |
| Madelon | 2,600 × 500 | classification | p ≫ n, mostly irrelevant features |

Three seeds on the two most expensive, five on the rest; the seed drives the 80/20 split
(stratified for classification), the model, and — for Friedman1 — the data itself.

**Protocol.** Both libraries are tuned per dataset by random search over a fixed space
with the same number of draws (10–24, larger where a fit is cheap). Draw zero is always
the library's own defaults, so a tuned row cannot be worse than its default row on the
selection fold; the hand-tuned configurations from Section 6 are entered as additional
warm starts. The search runs once per dataset on seed 0 and is reused across seeds, so
neither library tunes against the seed it is scored on. LightGBM's early-stopping fold
doubles as its selection fold, which is mildly generous to it; SXE early-stops on a fold
carved from the training half and is therefore selected on data it has not seen.

Both libraries receive the same preprocessed matrix — categoricals ordinal-coded,
numeric NaNs median-imputed from the training split — so the comparison is model against
model. A separate `LightGBM-native` row runs LightGBM on raw NaNs with declared
categoricals, which prices what SXE's missing features cost.

**Size** uses one formula on both sides (Section 3.7). **Time** is each library at its
own best thread count; on this 10-core machine LightGBM's best is one thread on seven of
nine datasets and SXE's is all cores on all nine.

**Accuracy: four to SXE, five to LightGBM.** Paired by seed, SXE's wins on Covertype-30k
(+0.0043 AUC, 5.0 sd, 5/5 seeds) and Madelon (+0.0158, 2.4 sd, 5/5) are clear, and so are
LightGBM's on Covertype-full (57.8 sd, 0/3), Adult (9.8 sd, 0/5) and Superconductivity
(3.1 sd, 0/5). California, Friedman1, Bank marketing and Letter are within seed-to-seed
spread, though the sign is consistent in each.

The pattern is coherent with what the method is. SXE's randomization is a
variance-reduction device: it wins where variance dominates — noise, p ≫ n, many
irrelevant features — and loses where bias dominates: large n, smooth strong signal,
correlated informative features. Covertype-full is the sharpest case: with 465k training
rows there is enough data to fit the bias away, and a sequential leaf-wise learner does
that better than an averaged forest of randomized trees.

**Size is not a systematic win.** SXE is smaller on five of nine and larger on four.
Neither search penalises size, so both columns report where an accuracy-driven search
happened to land; LightGBM's drifts to very large models (135k–497k leaves) when that
buys it anything. The 11.8× on California and 4.6× on Superconductivity are real but
they are not the same quantity as "SXE builds smaller models", and the report should not
claim they are.

**Speed**, at each library's best thread count, goes to SXE on three of nine. At a
user's likely setting — all cores for both — SXE would win most of them, because
LightGBM's within-tree parallelism costs it on data this size. That framing is available
and this report declines it.

### 7.2 What tuning buys each library

The gap between a library's tuned and default rows is the measurable form of "does this
need tuning". Error reduction from default to tuned, where error is RMSE or 1 − metric:

| Dataset | SXE | LightGBM | ratio |
|---|---|---|---|
| California | 4.4% | 1.0% | 4.3× |
| Friedman1 + noise | 1.9% | 3.3% | 0.6× |
| Superconductivity | 11.8% | 2.4% | 5.0× |
| Covertype (30k) | 50.4% | 8.2% | 6.2× |
| Covertype (full) | 82.8% | 61.4% | 1.3× |
| Adult | 4.5% | 2.7% | 1.7× |
| Bank marketing | 2.6% | 0.9% | 2.9× |
| Letter | 36.8% | 6.7% | 5.5× |
| Madelon | 9.5% | 3.6% | 2.6× |
| **median** | **9.5%** | **3.3%** | **2.9×** |

**SXE gains more from tuning on eight of nine datasets.** This is the clearest negative
result in the report, and it is about the defaults rather than the method: the tuned SXE
column is competitive, the default one is not.

The winning configurations say what is wrong. Not one of the nine used the default
`max_depth_choices=(4,5,6,7,8)` — five chose (8,10,12) or (10,12,14), four chose
leaf-wise growth with 63–127 leaves. `max_iter` selected the top of its range on seven
of nine and `batch_size` on six. Three of the knobs that matter most therefore ran into
the ceiling of the search space, which means the defaults are not merely mistuned but
systematically build too small a model, and the true optimum lies beyond what was
searched.

### 7.3 What SXE's missing features cost

`LightGBM-native`, run on raw NaNs with declared categorical columns, versus the same
LightGBM configuration on the imputed ordinal-coded matrix both libraries share:

| Dataset | LightGBM (shared matrix) | LightGBM-native | difference |
|---|---|---|---|
| Adult | 0.9305 auc | 0.9304 auc | −0.0001 |
| Bank marketing | 0.9338 auc | 0.9351 auc | +0.0013 |

Native categorical handling and native missing-value handling buy LightGBM almost
nothing on these two datasets. SXE's gap on Adult (−0.0065 auc) is therefore a model
gap, not an encoding gap — a useful negative result, since it says native categorical
support would not have closed it. What the missing features cost is user effort, not
accuracy: the preprocessing has to happen, and today the user has to write it.

**RandomForest context (v1 measurements, single seed, not re-run):** California 0.511
RMSE / 33.8 s; Friedman 1.443 / 116 s; Covertype 0.9486 AUC / 11.5 s. Every SXE version
from v1 onward beats RF on accuracy and time by wide margins. Those v1-era model sizes
were pickled sklearn objects and are not comparable to the size column above.

## 8. Honest caveats

**The defaults are the largest gap between the method and a library someone can pick
up.** Section 7.2 quantifies it: a median 9.5% error reduction from tuning against
LightGBM's 3.3%, on eight of nine datasets. Everything in Section 7.1's SXE column is a
tuned SXE.

**Size is an outcome, not a controlled variable.** Both searches optimise accuracy
alone. Neither column answers the question the README's use case actually poses — what
accuracy is available under a size budget — and answering it would need the search to
record every draw's size, which it does not yet do.

**Measurement.** Model size is a compact-format estimate for both libraries, not a byte
count of either one's real serialization. LightGBM's actual format stores float64
thresholds and so needs no bin table, which the shared formula charges it for anyway.
SXE's own `Ensemble::serialize` currently writes ≈29 bytes per node against the
formula's ≈10.5, because it stores `gain` on every node, `feat`/`thr`/`left`/`right` on
leaves and `val` on internal nodes — none of which prediction reads. That is a defect in
the format, not in the accounting, but until it is fixed the advertised size is not the
size on disk. Timings are wall-clock on one 10-core machine and will not transfer. The
validation fold is used three times (early stopping, the weight fit, and now the
probability calibration), so all three are mildly optimistic on it; test sets were
touched only for final evaluation.

**Preprocessing.** Categorical columns are ordinal-coded and numeric missing values
median-imputed before either library sees them, because SXE rejects non-finite input and
has no categorical handling. Section 7.3 prices that: on this suite, almost nothing in
accuracy — but the user still has to write it.

**Cross-platform reproducibility.** Per-tree randomness is drawn through
`std::uniform_int_distribution` and `std::uniform_real_distribution`, whose algorithms
are implementation-defined. libstdc++, libc++ and MSVC produce different sequences from
the same seeded `mt19937_64`, so a given seed grows *different trees* on different
platforms. Results are bit-identical across `n_jobs`, across `hybrid_min` and across
repeated runs on one platform — all three are tested — but the figures above reproduce
exactly only on the same C++ standard library.

**Method limits.** The loss is squared error throughout (no logistic loss, no
second-order leaf values). `predict_proba` is now Platt-scaled on the validation fold,
which makes it a probability rather than a clipped regression score; `calibrate=None`
restores the old behaviour. Multiclass is a one-vs-rest reduction over the binary core,
costing one full ensemble per class — on Letter that is 26 ensembles, 650k leaves and
2.7× LightGBM's model for slightly worse accuracy. There is no missing-value handling
and no general categorical handling beyond binary EFB; features are capped at 256 bins.
`bundle_binary_features=True` assumes exclusivity it verifies only on the training data:
a predict-time row with two active members of a bundle is silently encoded as the first
of them.

**Resolved since the original report.** Model persistence exists — trees serialize to a
compact blob, so a fitted estimator pickles, deep-copies and travels to joblib workers.
Growth uses a `std::thread` pool rather than OpenMP. The array boundary is typed
(pybind11). `hybrid_min` is now a pure performance knob: both growers recurse
smaller-child-first, so it selects an implementation rather than a model. Concurrent
`fit` calls on a single estimator instance are still unsupported, as they are for
scikit-learn estimators generally.

## 9. Future work

**Unbuilt levers from the original design.** Three refinements were proposed when the
method was designed and have never been implemented or ablated. All three target leaf values
rather than tree structure, which is where the remaining California gap most plausibly lives:

* **Honest leaf values.** The holdout is already routed through every tree and its per-node
  `(cnt, sum, ssq)` are already accumulated for the pruning decision (Section 3.5) — but
  exported leaves carry *training* means. Re-estimating leaf values from the holdout (honest
  trees, as in causal forests) is nearly free given what is already computed.
* **Hierarchical shrinkage** (Agarwal et al., 2022): shrink each node's prediction toward its
  parent in proportion to sample counts, then delete nodes whose post-shrinkage contribution is
  ~0. Reported in the literature to often beat hard pruning on accuracy, and it composes with
  the existing bottom-up pass rather than replacing it.
* **Leaf-level re-weighting.** The weight fit currently operates on batch-average columns —
  coarser than per-tree, chosen for cost. The fine-grained end is a ridge or lasso over the
  leaf-membership matrix (RuleFit territory), which recovers accuracy that per-tree weights
  cannot express.

**Then, in expected order of value:** Newton (second-order) leaf values and a learning-rate
schedule, both aimed at the same California gap; a broad multi-dataset sweep to validate the
package defaults; logistic loss and a native multiclass objective; and a GPU port, for which
the batch structure is ideal — within a batch, all trees × all nodes at a depth × all
candidates reduce to gather/histogram kernels with no sort or argmax over raw values, and the
weight fit is one small GEMM plus coordinate descent.

## 10. Reproduction

```bash
pip install -e ".[bench]"
python benchmarks/bench_suite.py                  # the tables in Section 7, ~1.5 h
python benchmarks/bench_suite.py -d adult letter  # a subset
python benchmarks/bench_suite.py --seeds 0        # single seed, quick
python benchmarks/bench_suite.py --retune         # redo both random searches
```

Output lands in `benchmarks/results_suite.csv` and the selected configurations in
`benchmarks/tuned_configs.json`; both are committed as the provenance for the tables in
this report and in the README. Figures reproduce exactly only on the same C++ standard
library — see the cross-platform caveat in Section 8.

The prototype benchmarks still run, from a checkout, for the v1/v2 numbers:

```bash
cd reference
g++ -O3 -march=native -fopenmp -shared -fPIC sxe.cpp -o libsxe.so
python benchmark.py        # v1: RF + LightGBM baselines + Python SXE
python cpp_benchmark.py    # v2: multi-round C++ SXE
```

Datasets download via scikit-learn (`fetch_california_housing`, `fetch_covtype`); Friedman1 is synthetic with fixed seed. All randomness is seeded; C++ tree seeds derive from `splitmix64` per tree index, so results are independent of thread count.
