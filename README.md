# SXE — Sparse eXtra Ensembles

**Batch-boosted, holdout-pruned, sparsely re-weighted histogram trees, with a scikit-learn API.**

Against a **tuned** LightGBM across nine datasets, SXE wins on accuracy on six, ties
one and loses two, with a smaller model on eight of nine (1.4× to 21×, measured on the
bytes each library actually ships). Its predictions are **bit-identical regardless of
how many threads you run it on**.

```python
from sklearn.datasets import fetch_california_housing
from sklearn.model_selection import train_test_split
from sxe import SXERegressor

X, y = fetch_california_housing(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=0)

model = SXERegressor(random_state=0).fit(X_train, y_train)
preds = model.predict(X_test)
print(model.summary())
# {'n_iter': 120, 'n_trees_grown': 1200, 'n_trees_kept': 280, 'n_leaves': 8092,
#  'model_size_mb': 0.18, 'tree_size_mb': 0.166, 'bin_table_mb': 0.014, ...}
```

Those are the *default* parameters, not the tuned benchmark configuration — see
[Tuning](#tuning).

> **Status: alpha.** The API is not yet stable, and the benchmarks are three to five
> seeds on nine datasets, one machine. The defaults are the weakest part of the
> package — they give up substantially more to tuning than LightGBM's do. See
> [Caveats](#caveats) before relying on any of this.

## Install

Not on PyPI yet — install from a checkout. Building needs a C++17 compiler and
CMake; there is no OpenMP dependency, so no `brew install libomp` step on macOS.

```bash
git clone https://github.com/alastairrushworth/sxe
cd sxe
pip install -e .
```

Wheels for Linux, macOS and Windows on CPython 3.9–3.13 are built and tested on
every push, and pushing a `v*` tag publishes them. `pip install sxe` will work
from the first tagged release.

## What it does

Features are quantile-binned once into at most 256 histogram bins. A dictionary
of trees is then generated by *batch boosting*: small batches of randomized,
subsampled trees are grown in parallel against the current residual, added with
shrinkage, and early-stopped on a validation fold. Each tree is pruned on its
own out-of-subsample holdout at a randomized strength, so the ensemble spans a
spectrum of bias–variance trade-offs. Finally a single non-negative lasso over
batch-average prediction columns re-weights the boosting trajectory and
physically deletes the batches that contribute nothing — which is where the
size reduction comes from.

The full derivation, the ablations behind each component, and the honest
caveats are in the technical paper, [`paper/sxe.pdf`](paper/sxe.pdf) (LaTeX
source alongside it).

## Why you might use it

| | |
|---|---|
| **Small models** | Smaller than a tuned LightGBM on eight of nine benchmark datasets, by 1.4× (bank) to 21× (madelon), measured on what each library actually writes: SXE's blob plus its bin table against the leanest encoding of LightGBM's trees. Larger on friedman1 (1.7 MB vs 0.6). Worth checking on your data if the model ships to an edge device, into a container image, or through a serving path where load time matters. |
| **Reproducibility** | Per-tree RNG seeds derive from the tree index, never from scheduling order, so `n_jobs` is a pure performance knob: same seed, same predictions, bit for bit. This holds within a platform — the C++ standard library's random distributions are implementation-defined, so a seed grows different trees on Linux and macOS. |
| **Parallel structure** | Trees within a batch are independent. Only the batch-level residual update is sequential, so growth parallelises where sequential GBDT cannot. |

## Why you might not

- Missing values are handled — NaN gets its own bin — but nothing learns a
  per-split default direction, and against median imputation the two are within
  noise. Treat it as convenience, not accuracy. Infinity is still rejected: NaN
  means missing, infinity is a number the binning cannot place.
- No categorical handling beyond exclusive feature bundling for binary columns.
- No `sample_weight`.
- Multiclass shares one tree structure across classes (K-vector leaves) but still
  minimises squared error on one-hot targets, not a multinomial loss.
- Regression minimises squared error; classification now uses the logistic
  (multinomial) loss with Newton leaf values, but there is no Huber, quantile or
  Poisson objective.
- **The defaults give up more to tuning than LightGBM's do** — a median 9.5% error
  reduction against 3.3%, on eight of nine datasets. Budget for a search, or wait
  for better defaults; see [Tuning](#tuning).
- **It is not on PyPI yet.** Install from a checkout until the first tagged
  release; see [Install](#install).

## API

`SXERegressor` and `SXEClassifier` are ordinary scikit-learn estimators — both
pass `sklearn.utils.estimator_checks.check_estimator` in full, so they compose
with `Pipeline`, `GridSearchCV`, `cross_val_score` and `joblib` without
adapters.

```python
import joblib
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import GridSearchCV

pipe = make_pipeline(StandardScaler(), SXERegressor(random_state=0))
search = GridSearchCV(pipe, {"sxeregressor__learning_rate": [0.05, 0.15, 0.3]}, n_jobs=-1)
search.fit(X, y)

joblib.dump(search.best_estimator_, "model.joblib")   # the trees travel with it
```

Parameter names follow scikit-learn's `HistGradientBoosting*` vocabulary where
the concepts match — `learning_rate`, `max_iter`, `n_iter_no_change`,
`validation_fraction`, `max_bins`, `max_leaf_nodes` — so most knobs need no
translation. The genuinely SXE-specific ones are:

| Parameter | Default | Meaning |
|---|---|---|
| `batch_size` | `16` | Trees grown in parallel per boosting step. `1` recovers ordinary stochastic gradient boosting; one huge batch recovers a random forest. |
| `holdout` | `"batch"` | Every batch partitions the rows into `holdout_folds` folds; tree *t* grows on all but fold *t mod F* and prunes on it, so each tree sees 3/4 of the data and every row gets an honest out-of-batch prediction the weight fit uses. `"random"` is the older per-tree subsample. |
| `holdout_folds` | `4` | Folds per batch under `holdout="batch"`. |
| `subsample_range` | `(0.4, 0.75)` | Per-tree row subsample rate under `holdout="random"`; the complement is that tree's pruning holdout. |
| `prune_strength_range` | `(1e-3, 1.0)` | Per-tree holdout pruning penalty λ, sampled log-uniformly. Small λ removes only splits that do not help held-out data. |
| `max_depth_choices` | `None` | Per-tree depth, sampled uniformly; `0` means unlimited. `None` sizes trees to the data: `(6, 8, 10, 12)` below 20k training rows, `(8, 10, 12, 14)` to 100k, `(10, 12, 14)` above. |
| `min_samples_leaf_range` | `None` | Sampled log-uniformly per tree. `None` follows the same size rule: `(10, 60)`, `(5, 30)`, `(2, 15)`. |
| `max_features_range` | `(0.5, 1.0)` | Candidate-feature fraction, sampled uniformly per tree. |
| `splitter` | `"best"` | `"best"` scans all bins for the optimal cut; `"random"` draws `n_thresholds` random cut-points, trading split quality for member diversity. |
| `bundle_binary_features` | `False` | Exclusive feature bundling for binary columns. Worth enabling on wide one-hot data. |
| `weight_refit` | `"relaxed"` | Relaxed lasso for the batch weights: the penalty picks the batches, a non-negative least-squares refit undoes its shrinkage, and the two are traded off by cross-validation. `None` keeps the plain lasso. |
| `weight_tol` | `0.01` | Size preference in that fit: the sparsest solution within this fraction of the best cross-validated error. |
| `loss` | `"logistic"` | Classifier only. Trees grow on the log-likelihood gradient with Newton leaf values, softmax for K > 2; `"squared"` is the older 0/1 regression reduction. |
| `linear_leaves` | `0` | Regressor only, opt-in: ridge models in the bin ids of up to this many path features per leaf. Measured not to help at any tree depth tried — kept for experiment. |
| `multiclass` | `"vector"` | `"vector"` grows one ensemble whose leaves hold a K-vector, so the tree structure is shared across classes; `"ovr"` fits one binary ensemble per class. |
| `leaf_shrinkage` | `None` | Opt-in holdout-fitted step size per leaf (PaloBoost). Measured: small AUC gains on classification, slightly worse regression — hence off. |
| `hist_bits` | `0` | Opt-in quantized training: residuals rounded stochastically to this many bits per tree, splits scored from integer histograms, leaf values exact. |

`n_jobs=None` means *all cores* here, matching other gradient-boosting
libraries rather than scikit-learn's single-core default.

### Diagnostics

```python
model.summary()             # trees grown/kept, leaves, size, timings
model.feature_importances_  # split-gain, weighted by ensemble weight
model.n_iter_               # batches actually run before early stopping
```

## Tuning

The defaults do **not** reproduce the benchmark table, and the gap is larger than
it should be — see [The defaults are the weak point](#the-defaults-are-the-weak-point).
The per-dataset configurations found by the random search are in
[`benchmarks/tuned_configs.json`](benchmarks/tuned_configs.json); the search space
is in [`benchmarks/bench_suite.py`](benchmarks/bench_suite.py). Distilled guidance
from appendix B of [the paper](paper/sxe.pdf):

- **Smooth, low-dimensional signal**: fine trajectories. Small `learning_rate`,
  many batches, small `batch_size`, mild subsampling (0.85–1.0),
  `splitter="best"`, `max_leaf_nodes≈63`.
- **High-dimensional or one-hot data**: `max_depth_choices=(10, 12, 14)`,
  `splitter="random"` with `n_thresholds=3`, `bundle_binary_features=True`,
  moderate subsampling.
- **Noisy data with irrelevant features**: aggressive subsampling (0.2–0.4) and
  a large `learning_rate` with tight `n_iter_no_change`. This is where the
  speed comes from.

Across all nine searches the same three moves recurred: **deeper trees** (not one
winning configuration used the default `max_depth_choices`), **more batches**, and a
**larger `batch_size`**. If you only turn three knobs, turn those.

## Benchmarks

Nine datasets, three to five seeds each, one 10-core machine. **Both libraries are
tuned** by random search over a fixed space with the same number of draws — a win
over a misconfigured baseline tells you nothing. Draw zero is each library's own
defaults, so a tuned row can never be worse than its default row on the selection
fold. **Size** is what each library would actually ship: SXE's serialized blob plus
the bin edges its trees cut at; for LightGBM the leanest encoding of its trees (a
float64 threshold, explicit children, no bin table). **Time** is each library at its
own best thread count. Both searches were run under the current code; the SXE search
space is described in `paper/sxe.tex` §"An accuracy pass".

| Dataset | Metric | LightGBM | SXE | Size MB LGBM / SXE |
|---|---|---|---|---|
| california (20,640 × 8) | rmse ↓ | 0.4409 ± 0.0089 | **0.4396 ± 0.0082** | 3.771 / **1.243** |
| friedman1 + noise (25,000 × 25) | rmse ↓ | 1.0695 ± 0.0106 | **1.0347 ± 0.0130** | **0.632** / 1.673 |
| superconduct (21,263 × 81) | rmse ↓ | **9.3313 ± 0.2989** | 9.4895 ± 0.2719 | 7.466 / **0.484** |
| covtype binary (30,000 × 54) | auc ↑ | 0.9547 ± 0.0030 | **0.9576 ± 0.0036** | 1.308 / **0.437** |
| covtype full (581,012 × 54) | auc ↑ | 0.9977 ± 0.0001 | 0.9977 ± 0.0001 | 13.856 / **5.564** |
| adult (48,842 × 14) | auc ↑ | **0.9305 ± 0.0015** | 0.9247 ± 0.0017 | 0.612 / **0.158** |
| bank marketing (45,211 × 16) | auc ↑ | 0.9338 ± 0.0016 | **0.9367 ± 0.0021** | 0.224 / **0.165** |
| letter, 26 classes (20,000 × 16) | accuracy ↑ | 0.9661 ± 0.0018 | **0.9678 ± 0.0011** | 6.724 / **0.965** |
| madelon (2,600 × 500) | auc ↑ | 0.8873 ± 0.0084 | **0.9122 ± 0.0033** | 0.458 / **0.022** |

**Accuracy: six to SXE, one tie, two to LightGBM.** By paired seed differences, SXE's
wins on friedman1 (t = 7.9), bank (9.0), madelon (5.4) and covtype-binary (2.2) are
outside seed-to-seed spread and letter (1.8) and california (0.6) are within it;
covtype-full is an exact tie on AUC (log-loss 0.0607 vs 0.0609); LightGBM's wins on
adult (t = 36.7) and superconduct (2.7) are clear.

The shape of it: SXE's randomization is variance reduction. It wins where variance
dominates — noise, p ≫ n, many irrelevant features — and loses where bias dominates:
large n, smooth strong signal, correlated informative features.

**Size is a systematic win at tuned accuracy.** SXE's shipped model is smaller on eight
of nine — 21× on madelon, 15× on superconduct, 7× on letter, 3× on california and
covtype — and larger only on friedman1, where the search bought its 3% RMSE win with
213k leaves. Nothing in either search penalises size; LightGBM's search drifts to very
large models. The accuracy gains of the last pass cost size at *defaults*, though:
see the next section.

### The defaults are the weak point

The gap between each library's tuned and default rows is the honest measure of "does
this need tuning":

| | SXE | LightGBM |
|---|---|---|
| Median error reduction from tuning | **6.5%** | 3.3% |
| Datasets where tuning helps more | **5 of 9** | 4 of 9 |

The gap widened again in the last pass because the wider search found much better
configurations, not because the defaults got worse: at defaults SXE beats LightGBM's
defaults on bank, friedman1, madelon and covtype-full and loses on adult, california,
covtype-binary, letter and superconduct. Default models are also now larger than
LightGBM's defaults on most datasets (adult 0.57 MB vs 0.13, covtype-full 22 MB vs 2.5)
and fits are 5–20× slower — the price of trees that see 3/4 of the rows, Newton leaves
and a weight fit with less selection noise. `holdout_folds`, `weight_tol` and
`max_iter` are the dials that trade that back; the tuned column is where the size
claim holds.

Reproduce with:

```bash
pip install -e ".[bench]"
python benchmarks/bench_suite.py                  # everything, ~1.5 h
python benchmarks/bench_suite.py -d adult letter  # a subset
python benchmarks/bench_suite.py --seeds 0        # single seed, quick
```

Raw output is in [`benchmarks/results_suite.csv`](benchmarks/results_suite.csv) and
the selected configurations in
[`benchmarks/tuned_configs.json`](benchmarks/tuned_configs.json).

## Caveats

Read section 8 of [the paper](paper/sxe.pdf) before quoting any of this. In short:

- **The defaults do not reproduce the table.** They give up a median 9.5% to tuning
  against LightGBM's 3.3%. This is the largest gap between the method and a library
  someone can pick up.
- **Size is an outcome, not a controlled variable.** Both searches optimise accuracy
  alone, so the size column reports where each search happened to land rather than
  what either library can do under a size budget.
- **Size is an estimate for both**, not a byte count of either library's real
  serialization. LightGBM's format stores float thresholds and needs no bin table,
  which the shared formula charges it for anyway. SXE's own `serialize()` currently
  writes about 2.9× the compact estimate — that is a fixable defect in the format,
  not in the accounting.
- **Nine datasets, one machine.** Timings are wall-clock on a 10-core laptop and will
  not transfer.
- **Seeds are not portable across platforms.** The C++ standard library's random
  distributions are implementation-defined, so the same seed grows different trees
  under libstdc++, libc++ and MSVC. Within a platform, results are bit-identical
  across runs, thread counts and `hybrid_min`.
- **Categorical columns are ordinal-coded** before either library sees them, so the
  comparison is model against model rather than preprocessing against preprocessing.
  LightGBM run on declared categoricals instead scores within 0.0013 AUC of its shared-
  matrix row on both categorical datasets. Missingness is encoded as its own category
  level, so after encoding none of the nine datasets has a NaN left — the missing-value
  path is measured separately by
  [`benchmarks/bench_missing.py`](benchmarks/bench_missing.py).
